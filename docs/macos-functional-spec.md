# Mac functional contract and Windows acceptance inventory

Reviewed 2026-10-01 against the shipping Mac code, README, CLAUDE.md, architecture, API and
development docs and ADRs 0001–0022. This is the authoritative **migration acceptance inventory**;
the shorter Windows parity pages summarize it. A feature is not equivalent merely because its
button exists. Defaults, visibility, saved state, side effects, failure behavior and the complete
user flow below belong to the contract. Platform-specific APIs and materials may differ.

**Status legend:** `Present` means the Windows path exists in source and may have fixture evidence;
it does **not** certify live acceptance. `Partial` names a confirmed difference. `Missing` means
the shipping Mac behavior has no equivalent Windows path. `Adapted` is an explicit OS adaptation.
`Gate` needs native/hardware/live acceptance; `Internal` is model-only, not a shipping control.
`Planned` is absent on Mac too and must not be counted as a migration loss. The acceptance column
is a concrete scenario to execute; unrecorded scenarios remain open.

Mac citations below point to the defining code. Windows paths resolve under
`Windows/DevDeck.Windows.App` unless Core/worker is named. Evidence is in `.local_docs/EVIDENCE.md`
and its linked JSON reports; never use a real client deck for visual qualification. The companion
[machine inventory](macos-spec-inventory.json) records source/resource hashes, declarations and
localized controls. Run `python3 scripts/check-macos-spec.py`; on drift, review affected IDs before
explicitly refreshing it. This check catches scope changes, not semantic omissions or regressions.
